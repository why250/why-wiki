# Codex 远程连接的代理配置与分层验证

## 适用问题

[[codex]] 桌面 App 的远程连接失败时，界面提示、进程状态和后台网络状态需要一起核对。[[local-2026-codex-remote-vpn]] 记录了一个“多个实例”提示伴随后台连接超时的 Windows 案例。

## 可复用的判断方法

- **看进程关系**：桌面 App 的渲染和网络辅助进程不能直接算作多个主实例，还需检查父子关系与登录会话。
- **比较同一目标的直连和代理结果**：如果直连超时而显式代理收到响应，可以缩小到网络路径或代理生效范围，但尚不足以证明应用认证成功。
- **检查代理设置作用在哪一层**：Windows 系统代理、启动进程环境变量与 App 启动参数可能覆盖不同连接。对已有实例设置新的启动环境，并不能据此断定原实例已继承配置。
- **按层验证**：服务端有 HTTP 响应、后台日志显示已连接、手机成功完成实际操作，是三个不同的成功信号。以所需的使用层次判断是否修复。
- **保留验证时间**：最近一次状态文件可能已经覆盖历史结果；后台曾连接成功也不能说明现在仍然可用。

## 案例边界

该案例使用 [[v2rayn]] 本地代理，同时修改三类代理配置，没有隔离各项的效果。因此应复用排查顺序，具体端口、开关、脚本与版本则按环境确认。两端使用不同 VPN 仍成功，也不能推导为所有 VPN 组合都可用。
